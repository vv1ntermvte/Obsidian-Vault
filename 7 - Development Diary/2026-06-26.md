I also did some testing regarding the CRF editor:
#### CRF Editor naming conventions
location: CRF Editor > Section 6. and 7.

Sections 6. and 7. should probably be renamed from 'Visit to CRFs' and 'CRF to Blocks' to 'CRFs to Visit' and 'Blocks to CRF' respectively.

Right now, it sounds like Visits are assigned to a CRF but following the hierarchy, CRFs are actually assigned to Visits. The same goes for the relation between CRFs and Blocks
#### CRF editor data grid input is not being saved in certain cases
location: CRF editor > data grid

This seems to be related to CSNG-109 as the behavior is caused in similar situations

In certain cases, it is possible to input data into a cell of the data grid, hit the save button and the input not being saved. As is the case with CSNG-109, this seems to happen whenever the user writes data into a field and then clicks save before unselecting the field once. In these cases, a success message will be displayed at the bottom, but this last input will not have been saved (see screenshot)

In one case, the row will not be saved at all because the only input that was made wasn't registered as such because the field was not unselected before saving

In another case, the second field has not been unselected before saving, causing an error upon saving because no all necessary fields were filled out (Name and Label). Retrying the same thing but this time unselecting the second field as well before saving results in a success.

This behavior again can also be caused with other kinds of fields that are not automatically unselected after input, given the field type isn't automatically unselected after input
